# План развития: что делать дальше

Прототип закрывает игровые петли GDD целиком, но визуал, интерфейс и часть заделов — временные.
Ниже порядок работ, в котором проект проще всего довести до вертикального среза.

## 1. Первый запуск и стабилизация (1–2 дня)
- Открыть проект в Unity 6, создать сцену (**Эхо-7 → Создать сцену игры**), нажать Play.
- Пройти первые 2–3 игровых дня. Проверить постройку стен протяжкой, назначение расчёта, ночную волну, поставку в 08:00, сохранение (F5/F9).
- Код проверялся компиляцией, но не в живом редакторе. Ошибки времени выполнения (если будут) чинятся по стеку из консоли.
  Самые вероятные места — порядок инициализации в `Echo7Entry.Build()` и визуальные мелочи процедурных моделей.

## 2. Арт: замена заглушек на модели
Логика ищет у моделей только именованные узлы, поэтому префаб можно подставить, не трогая геймплей.

| Где | Что заменить | Обязательные узлы |
|---|---|---|
| `StructureModels.*` | постройки (реактор, стены, турели…) | турели: `#head` с дочерними `muzzle0..3`; ворота: `#door`; реактор: `#ring`, `#core`; командный модуль: `#beacon`; экстрактор: `#drill`; мина: `#lamp`; щит: `#dome` |
| `StructureModels.WallLink` | секция стены к соседу | — (вызывается на каждую сторону) |
| `CreatureRig.Build*` | существа | заменить на `Animator`, параметр скорости — из `Enemy` |
| `HumanoidRig.Build` | бойцы, игрок, VIP | `Muzzle` — точка выстрела |
| `WorldGenerator.BuildTerrain` | TerrainLayer'ы | индексы слоёв: 0 трава, 1 сухая трава, 2 грунт, 3 песок, 4 скалы |
| `WorldGenerator.BuildAcacia/BuildGrass` | деревья и трава | крона дерева — в узле `#canopy` (масштаб и цвет меняются от «зелёности») |
| `SoundManager.Override(Sfx, clip)` | звуки | — |

Подходящие пакеты (стиль референсов — светлый модульный sci-fi): POLYGON Sci-Fi Worlds / Sci-Fi Space (Synty),
Sci-Fi Modular Base Kits, Kenney Space Kit (CC0) для быстрых тестов.

Освещение: перейти на URP, добавить Volume с Bloom (оранжевые полосы станут сочнее), Color Adjustments
и ACES-тонмаппинг — это сразу приблизит картинку к референсам.

## 3. Интерфейс
- Перенести HUD и окна с IMGUI на UI Toolkit. Каждое окно уже выделено в свой метод `Draw*Window` (`UiWindows.cs`),
  данные берутся из менеджеров, поэтому перенос механический.
- Проверка рангов остаётся прежней: `UiManager.RequiredFeature(window)` + `PlayerRankManager.IsUnlocked`.

## 4. Данные в ScriptableObject
Каталоги `BuildingCatalog`, `EnemyArchetype`, `TurretProfile`, `SkillTree.Defs`, задачи Центра и визиты VIP
сейчас описаны в коде. Их стоит вынести в ScriptableObject, чтобы геймдизайнер настраивал баланс без программиста.

## 5. Заделы из GDD, которые стоит развить
- **Многоуровневые базы:** второй ярус сетки (`WorldGrid` с уровнем Z), полы, лестницы, турели на стенах.
- **Пещеры как локации:** сейчас пещера — богатые залежи у входа. Следующий шаг — отдельная подземная сцена с аддитивной загрузкой.
- **Орбитальная станция:** сцена-хаб с NPC высших чинов вместо окна торговли.
- **Синтетическая угроза:** на Северном плато — заводы ИИ. Добавить архетип синт-дрона (`ArmorClass.Synthetic` уже учтён
  в таблице урона) и событие активации при раскопках.
- **Фауна как оружие:** приманки и феромонные ловушки (см. ARCHITECTURE.md, п. 5).
- **NavMesh:** для сложной многоуровневой базы заменить A* по сетке на NavMesh с `NavMeshObstacle` у построек.
  Поле потока для штурма реактора лучше оставить: оно дешёвое и даёт поведение «ищем слабое место».

## 6. Технический долг
- `Game` (сервис-локатор) → DI (VContainer/Zenject) по мере роста.
- Пулы объектов для существ (сейчас они создаются и уничтожаются).
- Юнит-тесты на чистую логику: `ResourceBank`, `FlowField`, `GridPathfinder`, `EnemyOnslaughtDirector.Compose`, `PlayerRankManager`.
- Локализация (все строки сейчас на русском прямо в коде).
