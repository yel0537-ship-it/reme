# Баланс без программиста: ассеты ScriptableObject

Все цифры баланса собраны в шесть ассетов в папке `Assets/Echo7/Resources/Echo7Balance`.
Геймдизайнер меняет их в инспекторе Unity — код трогать не нужно.

| Ассет | Что настраивается |
|---|---|
| `Buildings` | постройки: название, описание, вкладка меню, прочность, броня, цена, время стройки, ранг/допуск/чертёж, энергия, койки, склад, шум, мораль, какие твари считают постройку целью |
| `Turrets` | стрельба турелей: дальность, скорострельность, урон и его тип, точность, разлёт, поворот, расход патронов и энергии, шум, износ, звук, цвет трассера; бонус дальности на втором ярусе |
| `Enemies` | существа: здоровье, броня, скорость, урон, дальность атаки, урон по постройкам, агрессия, «цена» в бюджете волны, с какого дня и ранга появляются, флаг сюжета, пайки за тушу |
| `Skills` | навыки: стартовые очки, сила за уровень, текст эффекта, макс. уровень, ранг, навык-предшественник |
| `Tasks` | задачи Центра: правила доски (сколько задач, штраф за провал, очко навыков за N задач, пороги KPI), стартовые задачи по порядку, пул случайных задач с весами и рангами |
| `Vips` | визиты высоких чинов: расписание, сами визиты с запросами («лучшее»/«похуже», цены растут с рангом), награды, шанс успеха, трибунал |

У каждого поля есть подсказка — наведите курсор на название поля в инспекторе.

## Первый запуск

При первом открытии проекта редактор сам создаёт недостающие ассеты из значений в коде (один раз на машину).
Если их нет — **Эхо-7 → Баланс → Создать или дополнить ассеты**.

Ассеты не обязательны: если какого-то нет, игра молча берёт значения из кода. Удалить ассет — значит
вернуться к «заводским» цифрам.

## Как работать

- **Правки во время Play применяются сразу.**
  - Цены, время стройки, энергия и радиусы энергосети меняются сразу.
  - Стрельба всех турелей меняется сразу.
  - У живых существ сразу меняются скорость, урон, дальность и темп атаки.
  - Задачи и визиты меняются со следующей выдачи.
  - Прочность, здоровье и броня меняются только у новых построек и существ: у существующих они уже выставлены.
- **Правки в Play-режиме сохраняются.** В отличие от объектов сцены, ассеты не откатываются после выхода из Play.
  Можно спокойно тюнить прямо в бою.
- **Проверка.** **Эхо-7 → Баланс → Проверить** (или шестерёнка ассета → «Проверить») ищет ошибки:
  дубли, невыполнимые задачи, шанс успеха выше 100%, циклы в навыках, отрицательные цены.
  Те же проверки выполняются при старте игры — замечания появятся в консоли.
- **Сброс.** Шестерёнка ассета → «Сбросить к значениям из кода» (Ctrl+Z отменяет) или меню
  **Эхо-7 → Баланс → Сбросить всё к значениям из кода…**.
- **Новые записи из кода.** Если программист добавил постройку или существо, выберите
  **Эхо-7 → Баланс → Создать или дополнить ассеты**. Новые записи допишутся, ваши значения не изменятся.
  Задачи и визиты дописываются только в пустой ассет: их содержимое целиком принадлежит дизайнеру.
- **Контроль версий.** Коммитьте `.asset` вместе с `.meta`. Ассеты — текстовые YAML, их удобно сравнивать в diff.

## Формулы

- **Рост с рангом.** Специалист = 0, Лейтенант = 1, Капитан = 2, Майор = 3, Полковник = 4.
  Цель задачи = `цель + за ранг × ранг`, дробная часть отбрасывается. Пример: 2 + 0.5 × ранг даёт 2, 2, 3, 3, 4.
  Цены запросов VIP считаются так же: `amount + perRank × ранг`.
- **Навыки.** Эффект = `уровень × perLevel`. Для процентных навыков perLevel — доля: 0.25 = +25%.
  Текст строится по шаблону `effectFormat`, где `{0}` = `уровень × perLevel × displayScale`.
  Экономия энергии и снижение шума ограничены 95%, снижение урона по постройкам — 90%.
- **Визиты.** Качество обеспечения считается по каждому запросу: лучшее = 1, «похуже» = `junkQuality`, отказ = 0.
  Итог — среднее по запросам. Шанс успеха миссии = `successBase + successPerQuality × качество`.
  Уникальная награда выдаётся, если качество не ниже `rewardQuality`.
  Трибунал — при провале миссии с качеством ниже `tribunalQuality`.
- **Волны.** Бюджет волны тратится на существ по их «цене» (`waveCost`). Дорогие существа приходят реже и малым числом.

## Что остаётся в коде и почему

Эти параметры определяют, *как* работает объект, а не *насколько он силён*. Их смена ломает логику или модели:

- **Второй ярус:** что держит ярус (стены, колонны) и что можно на него ставить (турели, сенсоры, энергоузлы).
  Цены настила, лестницы и колонны — в `Buildings`, бонус дальности турелей на ярусе — `elevatedRangeBonus` в `Turrets`.
- **Постройки:** размер в клетках (модели собраны под него), высота модели, протяжка стен, проходимость ворот,
  установка на залежь, сам класс поведения.
- **Турели:** режим огня — луч (лазер) или баллистика (тяжёлая турель).
- **Существа:** размер (модель и хитбокс), признак «фауна» (стадо или волна), дальний бой (плевок или выстрел).
- **Навыки:** какую систему усиливает навык. Например, «Скоростной монтаж» — стройку. Сила навыка при этом в ассете.
- **Задачи:** как засчитывается прогресс для каждого `TaskType`.
- **Визиты:** логика флагов наград (`bp_shield` открывает чертёж щита, `market_closed` — закрытый рынок). Сообщение и кредиты награды — в ассете.
- Ключи записей (`kind`, `id`) — это значения перечислений в коде. Новое существо или постройку
  добавляет программист (см. [EXTENDING](EXTENDING.md)), а цифры для них потом настраивает дизайнер.

## Для программиста

- Базовый класс — [Data/BalanceAsset.cs](../Assets/Echo7/Scripts/Data/BalanceAsset.cs). У ассета пять обязанностей:
  `ResetToCode()` (значения из кода), `AddMissingFromCode()` (дописать новое), `Validate()` (проверки),
  `ApplyLive()` (применить на лету) и `FileName`.
- Каталоги с ключами (`BuildingCatalog`, `TurretProfile`, `EnemyArchetype`, `SkillTree`) строят описания из кода
  и накладывают на них записи ассета (`Entry.ApplyTo`). Объекты описаний не пересоздаются — поэтому работает правка на лету.
- Задачи и визиты читают ассет напрямую (`BalanceData.LoadOrDefault`). Если ассета нет, создаётся временный экземпляр со значениями из кода.
- Новый параметр баланса добавляется так:
  1. поле в записи;
  2. строка в `From` (код → ассет) и в `ApplyTo` (ассет → игра);
  3. при необходимости — проверка в `Validate`.
  После этого дизайнеру достаточно выбрать «Дополнить ассеты»: существующие записи получат значение по умолчанию поля.
  Чтобы подтянуть значение из кода, нужен сброс конкретного ассета.
